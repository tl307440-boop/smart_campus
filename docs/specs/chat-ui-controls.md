# 对话界面控件与视觉一致性规格

状态：第一期、第二期大部分已实现（2026-10-15），第三期未开始  
范围：消息级小控件、等待态、错误态、操作反馈、后台文案与组件风格。前两节是新功能，后面几节来自《个人想法，仅供参考》那份反馈文档。

## 0. 实现记录

已做：

- **消息控件**（`MessageActions`）。助手消息有复制、重新回答、朗读三个按钮，用户消息有复制和编辑。容器是 `role="toolbar"`，左右方向键可以在按钮间切换，结果通过 `aria-live` 播报。桌面端 hover 时显示，触屏设备常驻，最新一条始终显示。
- **重新回答、编辑重发只作用于最后一轮**，而且直接覆盖，不保留多版本（第 10 节决定 1 取「直接覆盖」）。后端用 `replace_question` 把 Redis 和库里的最后一轮一起回滚，所以刷新后不会出现两份重复的问答。改中间某一轮要连带作废后面的所有轮次，库里的回滚会变复杂，这一期不做。
- **选中浮层**（`SelectionAsk`）：选中文字后可以「复制」或「就这段再问」，后者把选中内容作为引用块填进输入框。
- **键盘**：`Esc` 停止生成，`Ctrl/⌘ + ↑` 把上一条问题填回输入框。
- **回到最新**（`useStickToBottom`）：往上翻之后出现「回到最新」按钮，有新内容时带一个小圆点。
- **工具调用折叠**：答完后折成一行「查了 N 处」，点开能看到调用了哪些工具。
- **等待态**（`lib/chat-progress.ts`）：首字之前显示小懒头像、三个点和一行跟着阶段变的文案。文案沿用第 2.2 节的表，超过 8 秒没出首字时换成「有点慢，再等等我…」。
- **错误态**：错误卡片上有「再试一次」按钮。相邻且同类的错误合并成一张，并标「×N」。会话失效那一类不显示重试按钮。
- **toast**（`Toast.tsx`）：成功的 3 秒后自动消失，失败的要手动关闭。`AgentSettings`、`SchoolAiSettings`、`WorkspaceAdmin` 的保存结果都改走它。删除会话、复制也会提示。
- **后台术语**：已按第 5 节的表改名并加了说明。
- **表格**（`DataTable`）：结构化表格默认显示 8 行，下面是「展开其余 N 条」。超过 12 行时出现筛选框，按任意列匹配，范围是全部行而不只是显示出来的那几行。另有「复制表格」按钮，复制成制表符分隔的文本，可以直接粘进 Excel。
- **会话列表**（`SessionList`）：左侧抽屉，按今天、昨天、7 天内、更早分组。删除要点两步。

没做：

- 「有用 / 没用」反馈表、「存进记忆」按钮（第三期，决定 2 待定）。
- `support_contact` 与「用我自己的密钥」入口（决定 3、4 待定）。
- 时间戳。接口返回的消息还没有 `created_at`，加上要改 `Message` 模型，下一期再说。
- 长回答折叠、按钮三态（目前只有「保存中…」文字，没有转圈和完成勾）、高级设置折叠。
- 知识库逐个文件的上传结果提示。这一块的 `KnowledgePane` 和 `useDocuments` 正在被另一处改动修改，没有动。
- 第 6、7 节的视觉统一（需要设计稿）。

## 1. 消息级控件

### 1.1 现在的情况

`MessageBubble` 只渲染正文、出处纸条、求助卡片和（管理员可见的）情感调试块。消息上**没有任何操作入口**。用户想复制一段回答只能手动选中，想重问只能重新打一遍。

### 1.2 交互形态

控件排成一行，放在气泡下方。桌面端默认 `opacity-0`，`group-hover` 时淡入；移动端没有 hover，改为常驻但降低对比度（`text-muted`、`size-8` 的图标按钮）。正在流式输出的那条消息不显示控件，输出结束才出现。

图标沿用 `SketchIcons` 的手绘描边风格，和第 7 节的统一要求一致，不要混入线性矢量图标库。

### 1.3 助手消息上的控件

| 控件 | 行为 | 优先级 |
| --- | --- | --- |
| 复制 | 复制正文的 Markdown 源码。点击后图标变成勾、按钮文字变「已复制」，1.5 秒后恢复。`navigator.clipboard` 不可用时退回 `document.execCommand` | 高 |
| 重新生成 | 用同一个问题再跑一轮。新回答替换这一条，旧回答可以用「上一版 / 下一版」左右箭头翻回去（同一次提问的多个版本只在前端内存里，不入库） | 高 |
| 朗读 | Web Speech API 的 `speechSynthesis`，零后端成本。再点一次停止。对新生和视障用户都有用 | 中 |
| 有用 / 没用 | 点「没用」时展开一个单行输入问「哪里不对？」。写进一张反馈表，管理员能在后台看到「哪些问题答得差」——这对调知识库比任何指标都直接 | 中 |
| 存进记忆 | 把这条回答里的关键信息写进 `memory:{学校}:{用户}`，接现有的 `take_remember_command`。点击后弹一个可编辑的单行，默认填好摘要，确认才写 | 中 |
| 分享 | 复制一条指向这次会话的链接。依赖《聊天会话历史规格》落地后才有意义 | 低 |

### 1.4 用户消息上的控件

| 控件 | 行为 | 优先级 |
| --- | --- | --- |
| 复制 | 同上 | 高 |
| 编辑并重发 | 气泡原地变成输入框，改完回车。从这条开始之后的消息全部作废，重新往下跑。这比单纯「重新发送」有用得多——用户想重发通常是因为上一句没说清 | 高 |
| 重新发送 | 原样再发一次。适用于上一轮报错的情况 | 高 |

### 1.5 选中文字时的浮层

选中助手回答里的一段文字后，光标上方浮出两个按钮：「复制」和「就这段再问」。后者把选中的文字作为引用块填进输入框，用户接着写追问。这比让用户自己复制粘贴快得多，在长回答里尤其明显。

### 1.6 其他建议

- **键盘**：`Ctrl/Cmd + ↑` 把上一条自己发的消息填回输入框（终端习惯），`Esc` 停止生成。
- **时间戳**：hover 气泡时在角落浮出相对时间（「3 分钟前」），不常驻，不占空间。
- **滚动到底部**：用户往上翻之后，右下角出现一个圆形「回到最新」按钮，有新内容时带一个小圆点。
- **长回答折叠**：超过某个高度的回答默认折到一屏，底部渐隐 + 「展开全部」。
- **工具调用过程**：现在 `onTool` 事件推了「正在查教务系统」这类进度，但答完就消失了。改成折叠成一行「查了 2 处：教务系统、学校通知」，点开能看到调用了哪些工具、耗时多久。这对信任感的帮助比出处卡片还大。

### 1.7 无障碍

所有图标按钮都要有 `aria-label`。复制、重新生成这类操作的结果通过一个 `aria-live="polite"` 的隐藏区域播报。控件行用 `role="toolbar"`，左右方向键可以在控件间移动。

## 2. 等待态

### 2.1 现在的情况

首字到达之后有 `PencilIcon` 的 `pencil-bob` 动画跟在文字末尾。**首字之前什么都没有**——用户点发送后面对一片空白，而教务查询那一路要先登录 CAS、再查接口，这段空白可能有好几秒。

反馈文档第 8 条点的就是这个，给的参考是 DailyBean（吉祥物拿放大镜 + 环形进度 + 「正在寻找最受 20 多岁男性用户喜爱的积木…」）和原神地图工具（Q 版角色骑火箭 + 「向着星辰与深渊！…加载中~」）。共同点是：**一个角色在动 + 一句有人味的文案**，而不是干巴巴的「加载中」。

### 2.2 改法

首字之前显示一个等待气泡：小懒的 IP 形象（复用 `DeskPet` 的素材）+ 一行跟着进度变的文案。文案的数据源现成——SSE 已经在推 `status` 和 `tool` 事件：

| 阶段 | 文案 |
| --- | --- |
| 刚发出 | 小懒在想了… |
| 意图判定完、开始检索 | 小懒在翻学生手册… |
| `tool: jw_timetable / jw_grades / jw_exams / jw_free_rooms` | 小懒在登教务系统… |
| `tool: school_news / read_notice` | 小懒在看学校通知… |
| `tool: web_search` | 小懒在网上找… |
| `tool: campus_place / walking_route` | 小懒在看地图… |
| 超过 8 秒还没首字 | 有点慢，再等等我… |

不要做百分比进度条——我们不知道真实进度，假进度条比没有更糟。用一个循环动画（角色小幅摆动 + 三个点）就够了。

## 3. 错误态

### 3.1 已经修掉的部分

反馈文档第 4 条配的截图（`image10`）里是「服务端的模型密钥无效或还没配置，请检查后端的模型配置。」加一大段原始 401 JSON。当前代码里 `ErrorNote` 已经比那个好：`friendly-error.ts` 把文案换成了「学校的 AI 服务还没配置好或密钥失效了，请联系老师或管理员。」，原始报错折进 `技术细节` 且只对 `canDebug` 的人显示，还有一个「去 AI 服务看看」的按钮。那份反馈是对着旧版本提的。

### 3.2 还没有的

1. **重试按钮。** 现在出错后唯一的出路是手动再问一遍。错误卡片上应该直接有「再试一次」。
2. **联系方式。** 文档要的「联系管理员、学校电话」目前只有危机场景的 `counseling_contact`。建议在工作区设置里加一个通用的 `support_contact`（文字，管理员自己填，可以是辅导员电话或企业微信群），错误卡片在重试之后把它显示出来。
3. **重复错误合并。** `image2` 里同一个错误连着堆了三张一模一样的卡片。相邻且 `failure.kind` 相同的错误应该合并成一张，右上角标「×3」。
4. **学生看到的「去 AI 服务」。** 普通学生 `canConfigure` 为 false，按钮不显示，于是他只剩下干等。按反馈文档的意思，学生也应该能去填自己的密钥（`AgentSettings` 本来就是存在浏览器本地的个人密钥）——给学生展示一个「用我自己的密钥」入口，深链到那个面板。

## 4. 操作反馈

反馈文档第 6 条：保存和上传都没有明确的成功失败提示。

现状确认：`AgentSettings` 用 `setNotice("已保存：没填密钥，继续用学校的服务")`，`SchoolAiSettings` 用 `setNotice("已保存。")`，`WorkspaceAdmin` 用 `setNotice("已保存，约一分钟内对新提问生效")`——都是按钮下方一行灰色小字，视觉权重几乎为零，用户根本不确定点没点上。

改法：

- 加一个全局 toast（右上角，手绘描边卡片风格，成功 3 秒后自散，失败需手动关闭并带原因）。三处 `setNotice` 统一改走它。
- 按钮自身要有三态：默认 → 提交中（文字变「保存中…」，禁用，带转圈）→ 完成（图标变勾，2 秒后恢复）。
- 文档上传要有逐个文件的进度和结果，失败的文件单独列出来并说明原因（格式不支持 / 太大 / 解析不出文字）。
- `image3` 里知识库显示「共 32 篇 · 已索引 0」。如果这是真实状态，那是一个 bug 而不是 UI 问题，需要单独排查索引任务为什么没跑。界面上也应该把「未索引」解释清楚：加一行「未索引的文档不会被用来回答问题」和一个「现在就索引」按钮。

## 5. 后台术语

反馈文档第 9 条。对应 `image8`（「接口网址（Base URL）」「API 密钥 sk-…」）和 `image9`（「相似度阈值 0.00」「引用片段数 3」）。

| 现在 | 改成 | 下面加的灰色说明 |
| --- | --- | --- |
| 接口网址（Base URL） | 服务地址 | 一般不用改，除非用的是自建或中转服务 |
| API 密钥 | 密钥 | 在服务商后台复制，我们只存加密后的内容 |
| 相似度阈值 | 检索严格程度 | 滑块两端标「宽松（多找一些，可能不太相关）」和「严格（只要最贴切的）」 |
| 引用片段数 | 每次参考几段资料 | 多了回答更全，但会变慢 |

真正的技术名词（Base URL、top_k、threshold 的数值）折进一个默认收起的「高级设置」，给要排查的人用。

## 6. 品牌一致性：IP 形象

反馈文档第 5 条。`image3`（PC，IP 在左侧大片空白里）和 `image2`、`image13`（手机，IP 在右侧且很大）。

- 固定在同一侧。建议右下角，两端一致。
- 手机端尺寸降一档，并保证它永远不盖住对话正文和输入框。`Composer` 上已经有 `data-pet-avoid` 这个约定，把它扩展到消息区和控件行。
- 对话很长或输入法弹起时，IP 自动缩成一个小角标。

## 7. 组件风格统一

反馈文档第 7 和第 10 条。

- **字体层级**：标题 / 正文 / 说明三级要拉开。说明文字降对比度（用 `text-muted`）、小一号、行高放松。现在后台的标签和内容字号接近，挤成一团。
- **图标**：`image12` 里页头三个按钮是「描边圆角方 + 描边圆角方 + 粉色实心正圆里写汉字『系』」。统一成同一种形状（都用 `sketch` 描边圆角方），统一用图形而不是汉字，粉色实心只留给页面上唯一的主操作。
- **输入框**：`image13` 里是下划线式极简输入框，和周围的手绘描边卡片不是一个语言。改成同样的 `sketch` 描边。
- **发送按钮**：截图里禁用态的灰白文字在粉色底上对比度不足，看不清是禁用还是可点。禁用态改成降饱和度 + 明确的 `cursor-not-allowed`。
- **卡片**：出处纸条、错误卡片、求助卡片、toast 共用一套描边、圆角、阴影和倾斜角度参数，抽成 CSS 变量。

## 8. 分期建议

| 期 | 内容 |
| --- | --- |
| 第一期 | 1.3 和 1.4 里标「高」的控件（复制、重新生成、编辑并重发、重新发送）、第 2 节等待态、第 4 节 toast 和按钮三态 |
| 第二期 | 1.5 选中浮层、1.6 的工具调用折叠和回到底部、第 3 节错误态四项、第 5 节后台文案 |
| 第三期 | 1.3 的反馈表和存进记忆、第 6 和第 7 节的视觉统一（需要设计稿配合） |

## 9. 非目标

- 不换 UI 框架，不引入组件库。现有的手绘风格是产品特征，组件库会把它冲掉。
- 不做消息的多版本持久化。「重新生成」的历史版本只活在前端内存里。
- 不做富文本编辑器。「编辑并重发」就是一个 `textarea`。
- IP 形象本身的重绘不在这份规格里，这里只管位置、尺寸和避让。

## 10. 请审查的决定

1. 「重新生成」要不要保留多版本切换，还是直接覆盖。
2. 「有用 / 没用」的反馈要落库（新表）还是只记日志。
3. `support_contact` 加在工作区设置里，由每所学校自己填——确认这个位置合适。
4. 学生能不能从错误卡片直接进「用我自己的密钥」。这会让学生接触到 API 密钥的概念，和第 5 节「少用术语」有点冲突。
5. 分期是否按第 8 节切。
