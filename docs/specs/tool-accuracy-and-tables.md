## 0. 实现记录

第 7 节的决定按这样落地：

- **决定 1：硬路由词表进这一期。** 教务词表和时效词表放在 `agent.py`。教务工具可用且问题命中时，直接走 TOOL，不调分类模型。「成绩差怎么办」这类倾诉由 `comfort.looks_like_venting` 先拦，仍然走陪伴。「那上学期呢」这种短追问，在上一轮是工具问答时沿用 TOOL。

## 1. 成绩是假的：成因与修法

### 1.1 为什么会编

`intent_node` 把问题分成 RAG / COMFORT / TOOL / DIRECT 四类，`route_query` 据此分流。**禁止编造的规则只写在工具问答那一条路径上**——`agent.system_prompt` 里的「涉及具体事实（课程、时间、教室、成绩、通知内容、地点）必须以工具结果为准，不要编造；查不到就直说」。

另外两条路径没有这句话：

- **DIRECT**：`graph_app._generate` 里那段「你性格温暖、友善、幽默，像一个贴心的学长/学姐」的提示词，不含任何事实约束，`temperature=0.8`。
- **RAG**：走知识库检索。学生手册里当然没有某个人的成绩，模型拿着不相关的 context 照样会往下编。

于是只要分类器把「我这学期成绩怎么样」判成 DIRECT 或 RAG，就会得到一段读起来很像真的假成绩。用户换一句更明确的说法（「查一下我的成绩」），分类器命中 TOOL，才返回真数据。这正好对上「我再提示一下才会返回准确的」。

分类器本身也不稳：`max_tokens=10`、`temperature=0.1`，结果靠 `"TOOL" in raw_result` 这种子串判断，模型多说一个字就可能落到别的分支。而且它只看当前这一句，不看上下文——「那上学期呢」单独拿出来，判成 DIRECT 很正常。

### 1.2 改法

**（a）个人教务问题走硬路由，不问分类模型。** 在 `intent_node` 调模型之前加一层确定性判断：教务工具可用（`jw_mode` 不是 off、且 `user_id` 非空）且问题命中个人教务词表时，直接 `intent = "TOOL"`。

词表按工具分组，便于以后维护：成绩、绩点、学分、挂科、补考、重修、排名；课表、上什么课、第几节、今天有课吗、明天的课；考试、考场、座位号、监考；空教室、空的教室、自习室、哪间教室没人。

关键词匹配比模型稳定，而且省掉一次 API 往返。代价是极少数情况下会把「成绩差怎么办」这种倾诉误判成查询——工具查出来之后模型照样能共情，而且 `comfort.looks_like_venting` 的判断可以排在硬路由之前，先于它拦截。

**（b）禁止编造的规则下沉到所有路径。** 把下面这段加进 DIRECT 和 RAG 的系统提示词，不再只给工具问答：

> 你没有任何渠道知道这个学生的成绩、课表、考试安排、学分和排名。被问到这些而手上没有查询结果时，不要给出任何具体的课程名、分数、时间、教室或数字，直接说你去查一下，或提示他在「工具 → 教务账号」里绑定。

**（c）DIRECT 的 `temperature` 从 0.8 降到 0.5。** 0.8 是为了让闲聊有人味，但同一个参数也在放大编造。0.5 仍然不呆板。

**（d）工具查空时要显式说明。** `agent._exams` 在没有考试时会带一条 `note`，`_grades` 没有。空数组交给模型，它很容易自由发挥。给 `_grades`、`_free_rooms` 补上同样的 `note`。

### 1.3 不改的

不动模型本身，不加微调，不引入第二个模型做事实校验。上面四条都是提示词和路由层面的改动，可回退。

## 2. 不主动联网搜索

### 2.1 为什么不搜

三处叠加：

1. `web_search` 工具只在 `intent == "TOOL"` 时存在。分类提示词里关于联网的描述只有「或需要【联网查最新信息】」半句，而模型对「我需不需要联网」这个判断天然偏保守——它倾向于认为自己知道。
2. `agent.system_prompt` 的规则列表有四条，分别讲事实、教务、通知、地图，**完全没有提 web_search**。模型没有被告知什么时候该搜。
3. `_SEARCH_TOOL` 的描述是「联网搜索最新信息。校内的事先用 school_news 或 search_knowledge。」——后半句在劝退。

### 2.2 改法

**（a）给 `system_prompt` 加一条规则：**

> 涉及会随时间变化的信息（今年的政策、最新的日期和价格、排名、校外的活动和新闻），或者你对某个事实没有把握时，先调用 web_search 再回答，不要凭记忆作答。多搜一次的代价远小于说错。

**（b）同样加硬路由兜底。** 命中时效词（今年、明年、具体年份、最新、现在、目前、最近、几号、还有多久、多少钱、排名、排行）且联网搜索工具可用时，直接 `intent = "TOOL"`。

**（c）把 `_SEARCH_TOOL` 的描述改成正向：**

> 联网搜索。遇到会过时的信息，或你不确定的事实，应当先搜再答。本校的通知和规章优先用 school_news 和 search_knowledge。

**（d）前端加一个「联网」开关。** 用户显式打开时，在这一轮的问题前注入一句系统指令强制先搜。现在用户只能靠在问题里写「联网搜索」来触发，不直观。开关的状态不进历史，只影响当前这一轮。

### 2.3 需要确认

`search_key(tenant_id)` 为空的学校根本没有这个工具，上面的改动对它们无效；`settings.query_only`（只按资料回答）的学校也不开放联网搜索。这两种情况下模型应该如实说「我查不了校外的信息」，而不是编。这一条归到 1.2(b) 的提示词里。

## 3. 空教室结果应该是表格

### 3.1 先纠正一个前提：这里用不上 OCR

`https://jwxt.whwl.edu.cn:8088/jwglxt/cdjy/cdjy_cxKxcdlb.html?gnmkdm=N2155` 这个页面，浏览器里看是表格，但它的数据来自同一地址的 `POST ?doType=query&gnmkdm=N2155`，返回的是 JSON：`{"items": [{"cdmc": ..., "cdlbmc": ..., "zws": ...}, ...]}`。`ZhengfangClient.free_rooms` 已经在打这个接口，`agent._free_rooms` 已经把它整理成 `[{"room": ..., "type": ..., "seats": ...}]`。

所以**没有任何图像需要识别**。开源 OCR（PaddleOCR、RapidOCR、Surya，以及做表格结构还原的 PP-StructureV3）解决的是「只有截图或扫描件、拿不到结构化数据」的场景。在这里引入 OCR 等于把已经是 JSON 的东西渲染成图片再认回来，纯粹是损失。

OCR 在这个项目里唯一有意义的位置是**知识库上传扫描版 PDF**——现在 `txt / pdf / docx / md` 的解析器对图片型 PDF 会抽出空文本。那是另一个问题，建议单开一份规格，不在这里展开。

### 3.2 真正的问题

问题出在「JSON → 用户屏幕」这一段交给了模型自由发挥。模型可能列成 bullet、可能漏行、可能把 40 行压成 10 行还不说明。前端 `Markdown.tsx` 其实已经完整支持表格（`kind: "table"`，含表头分隔线解析和 `overflow-x-auto` 包裹），所以只要模型吐出标准 Markdown 表格就能渲染——它只是没被要求这么做。

### 3.3 方案 A：提示词（低成本，先做）

在 `agent.system_prompt` 的输出规则里加：

> 工具返回多行结构化结果（空教室、成绩、课表、考试安排）时，用 Markdown 表格输出，列顺序照工具给的字段，不要省略行，不要改写数值。行数很多时先给表格再给一句总结。

这一条立刻生效，不改任何数据结构。缺点是仍然依赖模型照做。

### 3.4 方案 B：结构化表格事件（确定性，推荐）

让表格绕过模型。`agent.run` 已经有 `on_tool` 回调把 `{"tool": {...}}` 推给前端，`_agent_answer` 里是 `lambda event: writer({"tool": event})`。扩展它：

1. 工具的返回值里可以带一个 `_table` 字段：`{"columns": [{"key": "room", "label": "教室"}, ...], "rows": [...]}`。`_free_rooms`、`_grades`、`_timetable`、`_exams` 各自声明自己的列。
2. `run_tool` 把 `_table` 摘出来，**不**放进交给模型的 JSON 文本里（模型只拿到前若干行的精简版，省 token），而是随 `state: "done"` 的工具事件一起推给前端。
3. 前端收到就渲染一个真表格组件，插在这条助手消息里。模型照常用文字做总结（「3 号教学楼下午 1-2 节有 6 间空着」），但**表格的每一行都是接口原文，模型碰不到**。

这顺带解决三件事：现在 `rooms[:40]` 的截断可以只截给模型的那一份，表格给全量；模型不会改写数值；token 省下来。

代价：`chat_messages` 要加一列 `tables JSON`，否则刷新页面后表格消失。处理方式和现有的 `sources` 完全一样，已经在《聊天会话历史规格》第 14 节记为待审查项 9。

建议 A 和 B 都做：B 是主路径，A 作为旧消息和模型自己整理数据时的兜底。

### 4.2 空闲教室——已实现，但有三个缺口

你给的那条 URL 对应 `ZhengfangClient.free_rooms`（`jw_zhengfang.py`），周次 / 星期 / 节次都已经按位图编码（`zcd = 1 << (week-1)`，`jcd = Σ 1 << (period-1)`），对外暴露为 `jw_free_rooms` 工具。要补的是这三处：

1. **楼名过滤会静默失效。** `agent._free_rooms` 里 `rooms = [r for r in rooms if building in r["room"]] or rooms`——过滤不中就退回全量。而正方的 `cdmc` 常常是「1-101」这种不带楼名的编号，按「3 号教学楼」过滤必然落空，于是返回全部却看起来像过滤过了。改法：`free_rooms` 一并取出 `jxlmc`（教学楼名）和 `lh`（楼号）参与匹配；仍然匹配不到时，在返回里明说「没有名字含『X』的教学楼，下面是全部结果」。
2. **截断没有告诉模型。** `rooms[:40]` 之后模型会把 40 当成全部。补一个 `truncated: true` 和总数。方案 B 落地后，给模型的截断和给前端表格的全量各走各的。
3. **场地类型过滤会误伤。** `if any(word in str(r.get("cdlbmc", "")) for word in ("教室", "机房", "实验"))`——`cdlbmc` 为空的行会被整个丢掉。改成空值时保留。

## 5. 测试

- 问「我这学期成绩怎么样」「上学期绩点多少」「明天有课吗」「哪间教室空着」，每句都走到 TOOL，不经过分类模型。
- 未绑定教务账号时问成绩，回答里不出现任何课程名和分数，只有绑定引导。
- 教务工具返回空数组时，回答是「这学期还没有成绩」而不是编一份。
- 问「今年的国家奖学金什么时候申请」，在有联网 Key 的学校里会调用 `web_search`。
- 没有联网 Key 的学校问同样的问题，回答明确说查不了校外信息。
- 空教室查询的结果里，表格行数等于接口返回行数（不被 40 截断），且每个教室名与接口原文逐字相同。
- 按不存在的楼名过滤时，返回里带有「没有匹配的教学楼」的说明，而不是静默给全量。
- `summary` / 压缩相关的交互见《聊天会话历史规格》第 12 节。
